# Spectator game mode

Game mode renders recorded or synthetic H1 dialogue as codes for spectators. Reviewers receive separate logs containing the exact H1 and its expanded fields. Normal agent coordination remains readable in the usual transcript. Deliver the spectator output to players and the reviewer log to reviewers.

G2 uses a shared codebook of exact messages and reduces token counts when dialogue repeats. G1 uses tokenizer IDs and supports messages directly from their text. Both formats have public decoders. Players with the corresponding vocabulary or codebook can recover the messages.

## G2 shared codebook

Use G2 for games with a reusable dialogue vocabulary. The `book` command derives it from any valid dialogue, preserving the first occurrence of each exact H1 string. The codebook lives with the game host and reviewers. Spectators receive a stream header binding the codebook's SHA-256 hash, followed by records containing message IDs, routes, and integer references.

Use Python 3.9 or later with `uv`. Run from the repository root. These commands create a fresh directory, build a codebook from the included [dialogue](game-dialogue.jsonl), and verify reviewer replay.

```bash
game_output=$(mktemp -d)
uv run --isolated --with tiktoken==0.12.0 python -B compact-agent-handoffs/scripts/game.py book compact-agent-handoffs/references/game-dialogue.jsonl --output "$game_output/codebook.json"
uv run --isolated --with tiktoken==0.12.0 python -B compact-agent-handoffs/scripts/game.py encode compact-agent-handoffs/references/game-dialogue.jsonl --format G2 --codebook "$game_output/codebook.json" --reviewer-log "$game_output/reviewer.jsonl" > "$game_output/spectator.jsonl"
uv run --isolated --with tiktoken==0.12.0 python -B compact-agent-handoffs/scripts/game.py decode "$game_output/spectator.jsonl" --codebook "$game_output/codebook.json" > "$game_output/replayed.jsonl"
cmp "$game_output/reviewer.jsonl" "$game_output/replayed.jsonl"
```

Reuse the same codebook for subsequent rounds. Each batch needs unique message IDs and a fresh reviewer log path. Text, whitespace, and trailing newlines must match a codebook entry exactly. Add new dialogue by building a new codebook at a new path and using its matching stream header. An unknown message or a mismatched codebook produces an error before spectator output.

The event `{"id":"m1","from":"scout","to":"builder","ref":0}` references the first codebook message. Replay expands it into a `G2-review` record with the codebook hash, reference, original metadata, exact H1, and expanded fields. Existing codebook and reviewer files are preserved. Both the encoder and decoder validate the whole batch before publication, and the complete reviewer log is published before the spectator stream.

## G2 benchmark against H1

The benchmark generates a codebook from the sixteen existing [H1 fixtures](benchmark.json), then sends that vocabulary once, twice, or ten times in one stream. Each event has a unique ID and identical routing metadata in the H1 and G2 variants. The codebook is generated by the same public implementation used by the CLI.

Warm counts include every spectator record, its JSON keys, punctuation, IDs, routes, final newlines, and one codebook-binding stream header. Cold counts add the entire codebook. Each line is tokenized separately with `tiktoken` 0.12.0. The codebook costs 294 tokens under either encoding, and the header costs 44.

| Encoding | Vocabulary cycles | Messages | H1 events | G2 warm | G2 cold | Cold reduction |
| --- | --- | --- | --- | --- | --- | --- |
| o200k_base | 1 | 16 | 678 | 453 | 747 | -10.2% |
| o200k_base | 2 | 32 | 1,356 | 862 | 1,156 | 14.7% |
| o200k_base | 10 | 160 | 6,780 | 4,134 | 4,428 | 34.7% |
| cl100k_base | 1 | 16 | 644 | 419 | 713 | -10.7% |
| cl100k_base | 2 | 32 | 1,288 | 794 | 1,088 | 15.5% |
| cl100k_base | 10 | 160 | 6,440 | 3,794 | 4,088 | 36.5% |

Both encodings count one vocabulary cycle's H1 bodies at 268 tokens and its reference bodies at 16. Those payload counts require the book and framing shown in the full-event table. For this workload, cold setup is offset by the second cycle. Savings depend on message reuse and lengths, and one-off dialogue can cost more than H1.

All H1 strings and expanded reviewer messages replay exactly. The ten-cycle reviewer log occupies 55,540 UTF-8 bytes. Reviewer storage is measured separately from spectator token counts. Sending the decoded reviewer logs to a model adds their tokens. These measurements exclude model instructions, tool envelopes, caching, and any game frontend. Encoding, display, and reviewer replay themselves make no model calls.

The benchmark commands at the end reproduce both G1 and G2 results. Use `--cycles 1 2 10` to select repetition counts explicitly.

## G1 tokenizer IDs

Each G1 spectator record carries a message ID, sender, recipient, encoding name, installed `tiktoken` version, and a numeric `tokens` array. The content uses actual tokenizer IDs. G1 is the default for existing `encode` commands. Select the new shared-book mode with `--format G2`.

Use Python 3.9 or later with `uv`. Run from the repository root. This example creates a fresh output directory for each run and uses the included two-message [dialogue](game-dialogue.jsonl).

The first run may download the Python package and tokenizer vocabulary. For offline play, run the example once with network access to warm both caches, then retain them on the game host.

```bash
game_output=$(mktemp -d)
uv run --isolated --with tiktoken==0.12.0 python -B compact-agent-handoffs/scripts/game.py encode compact-agent-handoffs/references/game-dialogue.jsonl --reviewer-log "$game_output/reviewer.jsonl" > "$game_output/spectator.jsonl"
uv run --isolated --with tiktoken==0.12.0 python -B compact-agent-handoffs/scripts/game.py decode "$game_output/spectator.jsonl" > "$game_output/replayed.jsonl"
cmp "$game_output/reviewer.jsonl" "$game_output/replayed.jsonl"
```

Use `cat "$game_output/spectator.jsonl"` for the encoded view and `cat "$game_output/reviewer.jsonl"` for the readable review. The commands also accept `-` for stdin. Use `--encoding cl100k_base` to select the other supported vocabulary. Replay uses the encoding and package version recorded in each event.

Input is UTF-8 JSONL with exactly four nonempty string fields per message.

```json
{"id":"m1","from":"scout","to":"builder","h1":"T inspect map for exits\nS ro"}
```

The corresponding spectator record has this form.

```json
{"format":"G1","tokenizer":"0.12.0","encoding":"o200k_base","id":"m1","from":"scout","to":"builder","tokens":[51,36665,4014,395,93706,198,50,974]}
```

Its reviewer record retains the exact H1 alongside the decoded meaning.

```json
{"format":"G1-review","tokenizer":"0.12.0","encoding":"o200k_base","id":"m1","from":"scout","to":"builder","h1":"T inspect map for exits\nS ro","decoded":"Task: inspect map for exits\nScope: Read only."}
```

The encoder validates the whole batch, checks unique message IDs, and derives reviewer text from the token IDs. It publishes a complete reviewer log before emitting any spectator records. Existing reviewer files are preserved. If spectator output fails after publication, the complete prepared dialogue remains in the reviewer log. Use a fresh log path when retrying a completed batch.

The decoder checks vocabulary/version metadata, integer token IDs, strict UTF-8, canonical ordinary encoding, and H1 syntax. Special-token spellings in H1 text are handled as literal text. Replay reconstructs the prepared dialogue, with ordinary H1 [field meanings](decoder.md).

## G1 benchmark against H1

The final serializer was measured on the same sixteen [H1 fixtures](benchmark.json). Every message is tokenized separately using `tiktoken` 0.12.0. Numeric array columns include brackets and commas. Event columns include all JSON keys, sender/recipient IDs, metadata, escaping, and the final newline.

| Representation | o200k_base tokens | cl100k_base tokens |
| --- | --- | --- |
| H1 message bodies | 268 | 268 |
| Numeric ID arrays | 713 | 709 |
| Plain H1 JSONL events | 646 | 612 |
| Full spectator JSONL events | 1,378 | 1,324 |
| Decoded reviewer JSONL events | 1,346 | 1,296 |
| Spectator plus reviewer events | 2,724 | 2,620 |

Numeric arrays cost 2.66 times the H1 bodies with `o200k_base`, and 2.65 times with `cl100k_base`. Including event envelopes, the spectator view costs 2.13 and 2.16 times the corresponding plain H1 events. This measures the cost of passing the rendered text to a model. Local encoding and display themselves make no model calls.

For the `o200k_base` run, spectator storage was 3,449 UTF-8 bytes and reviewer storage was 4,924 bytes. All sixteen H1 texts and expanded reviewer messages round-tripped exactly under both encodings. Token counts exclude model instruction loads, tool envelopes, caching, conversation replay, and any game frontend. The [H1 benchmark](token-measurements.md) separately measures handoff and instruction costs.

Reproduce the measurements and boundary checks with these commands.

```bash
uv run --isolated --with tiktoken==0.12.0 python -B compact-agent-handoffs/scripts/benchmark_game.py --encoding o200k_base
uv run --isolated --with tiktoken==0.12.0 python -B compact-agent-handoffs/scripts/benchmark_game.py --encoding cl100k_base
uv run --isolated --with tiktoken==0.12.0 python -B -m unittest discover -s compact-agent-handoffs/scripts -p test_game.py -v
```

The implementation uses the public ordinary encoding and strict decoding APIs documented in the pinned [tiktoken source](https://github.com/openai/tiktoken/blob/0.12.0/tiktoken/core.py).
